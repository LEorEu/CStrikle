## 我觉得现在应该把 §火力与 Grade 解耦 那份先停在实验状态

真正的问题不是：

> `1.23 Rating 到底映射 77 还是81？`

而是：

> **为什么 Grade 会让大家挤在这么窄的 Firepower 区间里？**

这才是我们应该先修的。

# 我会把整个工作重新分成三步

## 第一步：先定义“1–99到底意味着什么”

这个阶段甚至先别写代码。

Firepower 应该有一个玩家能理解的**语义标尺**。

比如只是方向示意：

| Firepower | 应该给人的感觉         |
| --------: | --------------- |
|     96–99 | 世代级/历史级火力峰值     |
|     92–95 | 世界最顶尖超巨巅峰       |
|     88–91 | 顶级明星、能长期Carry一线 |
|     83–87 | 一线明星 / 极强输出手    |
|     77–82 | 强一线选手           |
|     70–76 | 正常顶级赛事主力        |
|     62–69 | 一线偏弱 / 二线强手     |
|     52–61 | 明显偏弱枪位 / 功能型    |
|       <52 | 枪法确实是明显短板       |

重点不是我现在给的边界数字。

重点是以后你看到：

> donk 96

你应该立刻知道：

> “96意味着这个档次。”

然后再看另一个人91：

> “好，差5点不是随便抖出来的，而是确实差一个火力层级。”

现在系统没有这个语义。

现在更像：

> G5模板89，上下浮几分。

所以91和96到底差多大，其实没人知道。

# 第三步：建立“能力模型”，再让 Grade 成为其中一个先验

这一步才是真正重做 Draft。

我现在不会再写：

```text
G5 Rifle = 89 ± 4
G4 Rifle = 80 ± 4
G3 Rifle = 70 ± 4
```

而会改成：

> **Grade 给一个 Prior，而不是给一个笼子。**

比如概念上：

```text
G5 → 通常较强
G4 → 大概率强
G3 → 中间
G2 → 证据较弱

```

于是完全允许：

```text

G4 巅峰枪男       F93
G3 年轻怪物       F88
G2 新崛起选手     F82
```

这才符合：

> Grade = Career Evidence
>
> Firepower = Peak Ability

两个完全不同的问题。

# 老选手怎么办？

这恰恰是你原计划最漂亮的地方。

你不是要用：

> 老选手当年的5E Rating

直接生成。

而是：

> **先用现代可靠样本校准尺度，再把历史证据映射回这把尺子。**

例如知道：

> 现代一个真正统治级 Rifle Peak 大概应该是95～98。

那么看到某个历史选手：

> 当年Top3
> Major大赛统治
> 同时代公认第一枪男之一

就可以说：

> 那他也应该落在同一个“历史级峰值”区间。

不需要强求：

> “2014年的Rating到底和2026的1.28是不是一个算法。”

这解决了老数据不可比的问题。

---

## 所以老玩家不是“数据映射”，而是“证据映射”

类似：

因为我们的目标本来就不是体育科学模型。

是：

> **让CS玩家看卡的时候觉得“对，这差不多”。**
